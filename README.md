# NEXUS — Game Knowledge · Version 2

คลังความรู้หลายเกมสำหรับ Vercel ใช้ Next.js และ Supabase

## สิ่งที่ปรับปรุง
- หน้าใหม่: แถบเกมด้านข้าง พื้นที่อ่านสีสว่าง รายการคำถามที่สแกนอ่านง่าย และรองรับมือถือ
- รายชื่อเกมอ่านจาก Supabase ไม่จำกัดชื่อเกมในโค้ด
- เพิ่มเกม เปลี่ยนชื่อ คำอธิบาย และสีได้จากหน้าจัดการ
- เพิ่มและเผยแพร่คำถาม–คำตอบให้เกมใหม่ได้จากหน้าเว็บ
- แสดงจำนวนผลลัพธ์ทั้งหมดจริง แบ่งหน้าละ 24 / 48 / 96 รายการ พร้อมก่อนหน้า/ถัดไปและเลขหน้า
- ใช้ FAQ 360 รายการเดิมได้ครบ ไม่มีการลบหรือเขียนทับคำตอบเดิม
- กรองหมวดจากข้อมูลจริง เรียงตามชื่อหรืออัปเดตล่าสุด ค้นรหัส FAQ ได้
- รูปแบบรายการหรือการ์ด คัดลอกคำตอบ เปิดลิงก์ และแสดงแหล่งอ้างอิง
- ค้นด้วยคำสำคัญเป็นค่าเริ่มต้น ไม่มีค่า AI API ถ้าไม่ได้ตั้ง OpenAI key
- แสดงปุ่ม AI เป็นตัวเลือกเฉพาะเมื่อมีการตั้งค่าบริการแล้ว

## อัปเดตเว็บเดิมบน Vercel
1. แตก ZIP ด้วย Extract All แล้วเปิดโฟลเดอร์ที่มี `package.json`
2. อัปโหลดไฟล์และโฟลเดอร์ทั้งหมดไปแทนชุดเดิมใน GitHub โดยลากโฟลเดอร์ลงใน Add file → Upload files ด้วย
3. ตรวจว่า `app/page.tsx`, `app/layout.tsx` และ `package.json` อยู่ในโปรเจกต์เดียวกัน โฟลเดอร์ `app` ต้องอยู่ระดับเดียวกับ `package.json`
4. Root Directory ใน Vercel: เว้นว่างถ้า `package.json` อยู่ระดับแรกของ repository
5. Framework: Next.js / Node.js 22.x / Install: `npm ci` / Build: `npm run build` / Output: ค่าเริ่มต้น
6. ใส่ Environment Variables ด้านล่างแล้ว Redeploy

ZIP รุ่นนี้วางไฟล์โปรเจกต์ที่ราก ZIP โดยไม่มีโฟลเดอร์ `nexus-vercel` ซ้อนอีกชั้น

## ตั้งค่าบน Vercel

| Variable | ค่า | หน้าที่ |
|---|---|---|
| `SUPABASE_URL` | `https://esggoqvrwjdzszahzxlp.supabase.co` | ฐานข้อมูลเดิม |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key ที่ใช้อยู่ | อ่านและค้นข้อมูล |
| `SUPABASE_SECRET_KEY` | Secret key จาก Supabase → Settings → API Keys → Secret keys | เขียนข้อมูลจากเซิร์ฟเวอร์หลังตรวจรหัสผู้ดูแล |
| `ADMIN_ACCESS_KEY` | รหัสสุ่มเฉพาะของคุณอย่างน้อย 24 ตัวอักษร แนะนำ 32 ตัวขึ้นไป | ใช้เข้าสู่หน้าจัดการ |
| `OPENAI_API_KEY` | เว้นว่างได้ | เปิดตัวช่วย AI เมื่อมี key |
| `OPENAI_MODEL` | `gpt-4o-mini` | โมเดลสำหรับ AI ถ้าใช้ |

`SUPABASE_SECRET_KEY` คนละตัวกับ Publishable key ให้ใช้ key ที่ขึ้นต้น `sb_secret_` (รองรับ legacy service_role JWT ด้วย) ใช้เฉพาะ Environment Variables ฝั่งเซิร์ฟเวอร์ ห้ามใส่ใน GitHub หรือเปลี่ยนเป็น `NEXT_PUBLIC_`

`ADMIN_ACCESS_KEY` คือรหัสที่คุณตั้งเอง ไม่ใช่รหัสผ่านบัญชี Supabase หรือ Vercel ตัวอย่างวิธีสร้างรหัสสุ่มในเครื่องเมื่อมี Node.js:

```bash
node -e "console.log(require('node:crypto').randomBytes(24).toString('base64url'))"
```

เก็บรหัสนี้ไว้ใช้เข้าสู่หน้าจัดการ อย่าใช้ข้อความตัวอย่างหรือรหัสที่เดาง่าย การเปลี่ยนรหัสใน Vercel แล้ว Redeploy ทำให้รหัสเดิมใช้เขียนข้อมูลไม่ได้อีก รหัสผู้ดูแลคงอยู่เฉพาะในหน่วยความจำของหน้าจอ ไม่บันทึกใน localStorage และถูกล้างเมื่อออกจากโหมดผู้ดูแล/ปิดหน้าจัดการ

หากยังไม่ตั้งสองค่าผู้ดูแล ผู้เข้าชมยังอ่านและค้นข้อมูลได้ หน้าจัดการจะอธิบายวิธีตั้งค่าครั้งแรก

## เพิ่มเกมด้วยตัวเอง
1. กด **เพิ่มเกม / หัวข้อ** หรือ **จัดการ**
2. กรอก `ADMIN_ACCESS_KEY` ที่ตั้งไว้
3. แท็บ **จัดการเกม** → ใส่ชื่อ รหัสเกม คำอธิบาย และเลือกสี → **เพิ่มเกม**
4. รหัสเกมใช้ภาษาอังกฤษ/ตัวเลข/`-`/`_` เช่น `my-game` รหัสต้องไม่ซ้ำ และใช้เป็นตัวอ้างอิงถาวร เปลี่ยนชื่อที่แสดงภายหลังได้
5. เกมใหม่จะปรากฏในแถบเกมทันที ทุกอุปกรณ์อ่านรายชื่อเดียวกันจากฐานข้อมูล
6. แท็บ **เพิ่มหัวข้อ** → เลือกเกม → ใส่หมวด หัวข้อ และคำตอบ → **เผยแพร่หัวข้อ**

แก้ไขชื่อหรือสีเกม: คลิกชื่อเกมในหน้าจัดการ แล้วบันทึกการแก้ไข ข้อมูลหัวข้อเดิมยังเชื่อมกับรหัสเกมเดิม ระบบไม่มีปุ่มลบเกมเพื่อไม่ให้หัวข้อกำพร้า

หน้าจัดการนี้เป็นการใช้รหัสร่วมสำหรับเจ้าของเว็บ ยังไม่ใช่ระบบสมาชิกหรือสิทธิ์ผู้ดูแลหลายระดับ ผู้มีรหัสสามารถเพิ่ม/แก้เกมและเผยแพร่หัวข้อได้ ไม่มีการเปิดเผย Supabase Secret key ให้เบราว์เซอร์ และปลายทางจัดการไม่รับ SQL หรือชื่อตารางจากผู้ใช้

## ค้นหาและแบ่งหน้า
จำนวนหัวข้อคำนวณจากผลลัพธ์จริงตามคำค้น เกม และหมวด ระบบไม่จำกัดข้อมูลรวมไว้ที่ 60 แล้ว ค่าเริ่มต้น 24 รายการต่อหน้า (360 หัวข้อ = 15 หน้า) เลือก 48 หรือ 96 ได้

คำถามที่มีคำต่างจากข้อมูลมากอาจต้องใช้คำสั้นลง การค้นหาปกติเป็น keyword search ไม่ใช่ semantic/vector search ตัวช่วย AI เป็นทางเลือกและใช้ API แยกต่างหาก ถ้าเปิด AI บนเว็บสาธารณะควรเพิ่มการจำกัดอัตราเรียกใช้งานหรือเปิด Deployment Protection เพื่อควบคุมค่าใช้จ่าย API

## ทดลองในเครื่อง
ติดตั้ง Node.js 22 จากนั้น:

```bash
npm ci
```

คัดลอก `.env.example` เป็น `.env.local` แล้วตั้งค่า จากนั้น:

```bash
npm run dev
```

เปิด http://localhost:3000

```bash
npm run build
npm test
npm start
```

## การตรวจสอบที่ทำแล้ว
- Next.js production build และ TypeScript ผ่าน
- API tests: อ่านครบ 360 รายการใน 15 หน้า ไม่มีซ้ำ, offset ตามขนาดหน้า, ตัวกรองเกมใหม่, หมวด และ FAQ ID
- API tests: ปฏิเสธการเขียนเมื่อไม่มีการตั้งค่า/รหัสผิด, ตรวจข้อมูลก่อนเขียน, เพิ่มเกมและหัวข้อด้วยสิทธิ์ผู้ดูแล
- ทดสอบ Supabase จริงใน transaction แล้วย้อนคืน: เพิ่มเกมที่สามได้, ข้อมูลเดิมยัง 360, ผู้เข้าชมทั่วไปไม่มีสิทธิ์ INSERT เกมหรือหัวข้อ
- Supabase security advisor ไม่มีรายการแจ้งเตือน ณ เวลาตรวจ
- ยังไม่ได้อัปโหลดขึ้น Vercel ของคุณหรือทดสอบผ่านเบราว์เซอร์จริงในรอบนี้ และไม่ได้ทดสอบ AI ด้วย key จริง

ใช้ dependency versions และ lockfile เดิม การ build ทดสอบใช้ dependencies ที่มีอยู่; การติดตั้งใหม่ต้องเข้าถึง npm registry ได้
