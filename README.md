### นำเข้าข่าวหรือ FAQ จากลิงก์ (ไม่ใช้ AI)

1. เข้าบัญชีผู้แก้ไขหรือผู้ดูแล → จัดการ → Import / Export
2. เลือกเกมปลายทาง → นำเข้าจากลิงก์
3. วาง URL บทความ แล้วกด “ดึงข้อความจากลิงก์”
4. ตรวจชื่อ เนื้อหา และหมวดหมู่ที่เสนอจาก keyword แก้ไขให้ตรงกับต้นฉบับ
5. กดตรวจข้อมูลซ้ำ แล้ว “ยืนยันส่งร่างให้ผู้ดูแลตรวจ”
6. ผู้ดูแลเปิดแท็บรอตรวจสอบ ตรวจแหล่งอ้างอิง แก้ข้อความ/หมวดหมู่ ตรวจหัวข้อคล้าย และอนุมัติหรือปฏิเสธ

รองรับ HTML ที่มีข้อความให้ดึงได้ ไม่ใช่การค้นทั่วอินเทอร์เน็ต ไม่อ่านรูปเป็นข้อความ และไม่เรียบเรียงคำตอบด้วย AI ข้อความที่ดึงมาอาจมีเมนู/ส่วนอื่น จึงต้องมีผู้ตรวจ หากเว็บโหลดด้วย JavaScript เช่นหน้าข่าวบางหน้าของ TOSM ระบบจะแจ้งเมื่ออ่านไม่ครบและให้คัดลอกข้อความต้นฉบับมาวางเองพร้อม URL ไม่มีการข้ามล็อกอิน/CAPTCHA

เริ่มต้นดึงอัตโนมัติได้จาก `tosm.exe.in.th` เท่านั้น หากมีแหล่งอื่นที่ได้รับอนุญาตให้นำมาใช้ เพิ่ม Environment Variable ใน Vercel เช่น:

```text
IMPORT_ALLOWED_HOSTS=tosm.exe.in.th,news.example.com
```

ใส่ hostname จริงคั่นด้วย comma ไม่ใส่ https:// หรือ /path แล้ว Redeploy ต้องอนุญาต hostname ปลายทางของ redirect ด้วย รองรับ HTTPS พอร์ต 443 เท่านั้น ระบบตรวจ DNS และตรึง IP สาธารณะในแต่ละคำขอ ป้องกันการดึงเครือข่ายภายใน ไม่ส่งคุกกี้หรือคีย์ Supabase ไปเว็บต้นทาง

### Import ข้อมูลแยกเกม

- เลือกเกมปลายทาง แล้วเลือกไฟล์ `.json` หรือ `.csv` แบบ UTF-8 สูงสุด **3 MB / 5,000 หัวข้อ** ต่อไฟล์
- JSON รองรับอาร์เรย์หัวข้อ หรือ `{ "entries": [...] }` ใช้ `examples/import-template.json` เป็นตัวอย่างได้
- CSV ต้องมี `title`, `content`; ตัวเลือก `summary`, `topic`, `category`, `tags`, `source_url`, `source_id`
- `tags` ใน CSV ใช้ JSON array เช่น `["FAQ","บัญชี"]` หรือคั่นด้วย `|`
- CSV รองรับ comma, เครื่องหมายคำพูด และข้อความหลายบรรทัดเมื่อครอบ field ด้วย double quotes ตามรูปแบบ CSV
- กดตรวจไฟล์ก่อน ระบบแสดงจำนวนใหม่/ซ้ำและตัวอย่าง 50 แถวแรก โดยตรวจทุกแถวในไฟล์
- ถ้ามีแถวผิดรูปแบบ ระบบปฏิเสธทั้งไฟล์และบอกหมายเลขรายการ ไม่มีการนำเข้าไว้ครึ่งหนึ่ง
- ยืนยันแล้วสร้างร่างใหม่เท่านั้น ไม่เขียนทับหัวข้อเดิม แม้ผู้นำเข้าจะเป็น admin ก็ต้องอนุมัติจากแท็บรอตรวจสอบ
- ชื่อเกมใน JSON เป็นข้อมูลประกอบ การนำเข้าจะใช้เกมปลายทางที่คุณเลือก ไม่สร้าง/แก้เกมโดยอัตโนมัติ และไม่คืน UUID เดิม

### Export ข้อมูลแยกเกม

จัดการ → Import / Export → เลือกเกม → Export → ดาวน์โหลด JSON หรือ CSV

- เฉพาะผู้แก้ไขและผู้ดูแลส่งออกได้
- ส่งออกหัวข้อของเกมนั้นทั้งหมดใน `game_entries` รวมที่ยังไม่เผยแพร่ ไม่จำกัด 60 รายการ
- JSON มี metadata ชื่อเกม คำอธิบาย สี และข้อมูลหัวข้อ ส่วน CSV เหมาะกับ Excel และระบบอื่น
- ไม่รวมร่างรออนุมัติ สมาชิก/สิทธิ์ หรือไฟล์รูปเกม จึงไม่ใช่ full database backup
- ข้อมูลส่งออกต้องไม่เกิน 3 MB; หากเกินให้แบ่งชุดข้อมูลด้วยเครื่องมือฐานข้อมูลก่อน รุ่นนี้ยังไม่มี UI แบ่งไฟล์ใหญ่
- หากไฟล์ที่ export มีเกิน 5,000 หัวข้อ ต้องแบ่งก่อน import ตามเพดานต่อไฟล์
- CSV มี UTF-8 BOM เพื่อรองรับภาษาไทย และเติม apostrophe ป้องกัน spreadsheet formula สำหรับค่าที่ขึ้นต้นด้วยเครื่องหมายอันตราย ตัวนำเข้าของ NEXUS คืนข้อความเดิมให้อัตโนมัติ ใช้ JSON หากต้องการแลกเปลี่ยนข้อมูลโดยไม่ผ่านการแปลงของ Excel
- การ import ไฟล์ export กลับเข้าเกมเดิมจะข้ามข้อมูลซ้ำ ส่วนเกมปลายทางใหม่จะสร้างร่างให้อีกครั้ง

### การตรวจซ้ำและอนุมัติ

- ตรวจชื่อ + เนื้อหาที่ตรงกัน (ไม่สนตัวพิมพ์ใหญ่/เล็กและช่องว่างขอบข้อความ) และ source_id ภายในเกมเดียวกัน
- ตรวจทั้งหัวข้อเดิมและร่างเดิม รวมถึงร่างที่ตรวจแล้ว การส่งไฟล์เดิมซ้ำจึงไม่สร้างร่างซ้ำ
- ถ้า source_id เดิมแต่เนื้อหาเปลี่ยน ระบบยังถือว่าซ้ำ ไม่อัปเดตหัวข้อเดิมอัตโนมัติ ให้แก้หัวข้อเดิมจากหน้าจัดการ
- ผู้ดูแลกด “ตรวจหัวข้อที่คล้ายในคลัง” เพื่อเทียบข้อความก่อนอนุมัติ การตรวจชื่อ/คำตอบใกล้เคียงไม่ใช่การยืนยันว่าเนื้อหาเหมือนกันทุกกรณี
- ก่อนอนุมัติมีการตรวจซ้ำและล็อกรายการใน transaction อีกครั้ง การอนุมัติซ้ำจะคืนสถานะเดิม ไม่เผยแพร่ซ้ำ
- ผู้ดูแลแก้ร่างก่อนอนุมัติได้ สถานะอนุมัติ/ปฏิเสธ/ซ้ำ พร้อมผู้ตรวจ เวลา และหมายเหตุถูกเก็บในฐานข้อมูล ส่วน payload เดิมเก็บไว้เทียบต้นฉบับ
- หมวดหมู่จากไฟล์เป็นหมวดที่เสนอ ผู้ดูแลเลือกหมวดเดิมหรือรับหมวดที่เสนอได้ก่อนเผยแพร่
- เมื่อลบทั้งเกม ต้องยืนยันลบหัวข้อรวมถึงร่างด้วยหากมีร่างค้างอยู่

### ผลทดสอบและขอบเขตการตรวจ

ผ่าน production build, TypeScript และชุดทดสอบอัตโนมัติ `npm test` ครอบคลุม:

- JSON/CSV ไทยไปกลับ, ข้อความหลายบรรทัด, quotes, formula injection, UTF-8 และข้อมูลผิดรูปแบบ
- API Import/Export/ร่าง/อนุมัติแบบจำลอง: viewer และ pending ถูกปฏิเสธ, preview ไม่เขียนข้อมูล, import เป็น pending เท่านั้น, editor อนุมัติไม่ได้, admin อนุมัติได้, duplicate retry และ CSRF
- การปฏิเสธ URL/IP ภายในเครือข่าย, hostname หลอก, HTML ผิดรูปแบบ และ fallback ของหน้าเว็บที่ไม่มีเนื้อหา
- Regression การค้นหาไทย/อังกฤษ สิทธิ์เดิม การลบ และ pagination
- บน Supabase จริงติดตั้ง schema สำเร็จ ตรวจ RLS/สิทธิ์ anon และทดสอบ RPC ปฏิเสธคำสั่งที่ไม่มีสิทธิ์ โดยไม่เปลี่ยนข้อมูลจริง

**ยังไม่ได้ทดสอบการคลิกผ่านเบราว์เซอร์หรืออนุมัติหัวข้อจริงครบวงจร:** เครื่องมือทดสอบไม่มี Chromium และดาวน์โหลดจาก CDN ไม่สำเร็จเพราะ timeout มีสคริปต์ `scripts/ui-test.mjs` เตรียมไว้สำหรับเครื่องที่ติดตั้ง Playwright/Chromium แล้ว สคริปต์นี้จำลอง API ไม่ติดต่อข้อมูล production ไม่รวมใน `npm test` เพื่อไม่เพิ่ม dependency ให้การ deploy

หลัง Deploy ให้ทดสอบด้วยไฟล์ตัวอย่าง 1 หัวข้อ: preview → ส่งร่าง → ผู้แก้ไขอ่านได้แต่อนุมัติไม่ได้ → ผู้ดูแลแก้/อนุมัติ → หัวข้อปรากฏในคลัง → export → import ซ้ำต้องถูกข้าม แล้วลบหัวข้อทดสอบตามต้องการ การทดสอบที่ผ่านช่วยลดความเสี่ยง แต่ไม่ใช่การรับรองว่าไม่มีบัคในทุกสภาพแวดล้อม

ไม่ต้องใช้ AI API หรือบริการสรุปแบบเสียเงิน แต่การรับส่งข้อมูล/ฐานข้อมูลยังนับในโควตา Vercel และ Supabase เดิม

### สิ่งที่เพิ่ม

- ผู้แก้ไข (editor) และผู้ดูแล (admin) ลบหัวข้อและเกมได้ ผู้เข้าชม (viewer) ไม่มีสิทธิ์ลบ ทั้ง API และ RLS
- ลบหัวข้อ: เปิดคำตอบ → ลบหัวข้อนี้ → ตรวจชื่อ → ยืนยันการลบ
- ลบเกม: จัดการ → จัดการเกม → เลือกเกมที่ต้องการแก้ไข → ลบเกมนี้ → พิมพ์ชื่อเกมให้ตรง → ยืนยัน
- ถ้าเกมมีหัวข้อ ต้องเลือก “ลบหัวข้อทั้งหมดในเกมนี้ด้วย” รวมถึงหัวข้อที่ยังไม่เผยแพร่ หรือย้าย/ลบหัวข้อเองก่อน จึงลบตัวเกมได้
- การลบทั้งเกมและหัวข้ออยู่ใน transaction เดียวกัน หากส่วนใดล้มเหลวจะไม่ลบค้างบางส่วน รูปเกมจะล้างหลัง transaction สำเร็จ หากล้างรูปไม่ได้จะแจ้งว่าเกมถูกลบแล้วแต่มีไฟล์ค้าง เพื่อไม่ให้กดลบซ้ำโดยเข้าใจผิด
- การลบเป็นการลบถาวร ไม่มีถังขยะ/Undo ในหน้าเว็บ หน้ายืนยันอธิบายผลกระทบก่อนทำรายการ
- หลังลบจะโหลดจำนวนและตัวกรองใหม่ และจัดหน้าผลลัพธ์ให้อยู่ในช่วงที่มีข้อมูล
- หมวดหมู่ของฟอร์มเพิ่ม/แก้ไขหัวข้อเป็น dropdown จากหมวดที่มีอยู่แล้ว แสดงหมวดของเกมที่เลือกก่อน ตามด้วยหมวดจากเกมอื่นในคลัง เกมใหม่จึงใช้หมวดเดิมได้ ไม่สร้างชื่อหมวดซ้ำจากการพิมพ์ต่างกัน; ฐานข้อมูลว่างใช้ “ทั่วไป” เริ่มต้น
- แยกพื้นหลังหน้าเกม การ์ด และแถบเมนูด้วยสีประจำเกมชัดเจนทั้ง Light/Dark หากเลือกสีฐานซ้ำ ระบบจัดโทนแสดงผลให้ต่างกันอัตโนมัติ พร้อมคงชื่อ/รูปเกมเพื่อให้แยกได้โดยไม่อาศัยสีอย่างเดียว
- คงการค้นหาไทย/อังกฤษ คำแนะนำ และการจัดอันดับจาก 1.3.1

### การตรวจสอบรุ่นนี้

ผ่าน production build/TypeScript และชุดทดสอบ API จำลองสำหรับ editor/admin delete, viewer denied, การยืนยันลบ, หมวดไม่อยู่ในรายการ และ regression การค้นหา ติดตั้ง SQL สำเร็จ ตรวจฟังก์ชันเป็น SECURITY INVOKER และ anon เรียกไม่ได้ รวมทั้งทดสอบการปฏิเสธคำสั่งเมื่อไม่มีสมาชิกโดยไม่ลบข้อมูลจริง ยังไม่ได้ทดสอบลบรายการจริงหรือ Deploy เว็บแทนผู้ใช้

## อัปเดตการค้นหา 1.3.1 (สำหรับผู้ติดตั้ง 1.3 แล้ว)

- ค้นคำบางส่วน ทั้งหัวข้อ คำตอบ หมวดหมู่ tags และรหัส FAQ

- แนะนำสูงสุด 6 หัวข้อหลังหยุดพิมพ์ 350 ms ทั้งไทยและอังกฤษ; คลิกหรือใช้ ↑ ↓ และ Enter เพื่อเปิดคำตอบ; Esc ปิดรายการ
- เคารพตัวกรองเกมและหมวดหมู่ที่เลือกทั้งคำแนะนำและผลค้นหา
- เรียง “เกี่ยวข้องมากที่สุด” เป็นค่าเริ่มต้น; ผู้ใช้เลือกเรียงชื่อ/วันที่เองได้
- รองรับพิมพ์ผิดเล็กน้อยและคำเรียกใกล้เคียง เช่น password → รหัสผ่าน, พาสเวิร์ด → รหัสผ่าน, download → ดาวน์โหลด โดยแสดงป้ายหัวข้อใกล้เคียง
- ตรวจการจับคู่ตรงก่อนใช้การประมาณ เพื่อไม่ให้คำใกล้เคียงกลบผลตรง
- ไม่สร้างคำตอบใหม่และไม่ใช้ AI API; เป็นการจัดอันดับข้อความกับพจนานุกรมคำใกล้เคียงที่แก้ได้ใน `lib/search-engine.ts` ไม่ใช่การเข้าใจเจตนาได้ทุกกรณี

ตัวอย่างทดสอบ: `เติมเงิน`, `เงินไม่เข้า เติมเงิน`, `รหัสผ่าน`, `บัญชี`, `การ์ด`, `ลืมพาสเวิร์ด`, `password`, `downlaod` และ FAQ ID

รุ่นนี้อ่านแถวที่ผู้ใช้มีสิทธิ์จาก Supabase เป็นชุดละ 500 แล้วจัดอันดับก่อนแบ่งหน้า ไม่จำกัดผลแค่ชุดแรก ไม่แชร์ cache ระหว่างบัญชี และคงการตรวจสมาชิก/RLS เดิมไว้ เหมาะกับคลังปัจจุบันประมาณ 361 หัวข้อ หากโตถึงหลายหมื่นหัวข้อควรย้ายการจัดอันดับเข้า search index ฝั่งฐานข้อมูลเพื่อลดการรับส่งข้อมูล

ชุดทดสอบครอบคลุมภาษาไทยที่มีสระ/วรรณยุกต์ คำบางส่วน หลายคำ สลับคำ คำผิด คำตอบที่ไม่มี keyword ในหัวข้อ คำที่ไม่มีผลลัพธ์ คำแนะนำ และการค้นครบ 1,361 แถวข้ามหลายชุด พร้อมตรวจ build/TypeScript อ่านข้อมูลจริงแบบ read-only เพื่อยืนยันสาเหตุแล้ว ไม่มีการแก้ข้อมูลหรือสิทธิ์ใน Supabase ในแพตช์นี้

ไฟล์เว็บ Next.js สำหรับอัปเกรดเว็บ NEXUS เดิมบน Vercel โดยใช้ฐานข้อมูล Supabase เดิม ข้อมูลเกมและ FAQ ไม่ได้รวมอยู่ใน ZIP และไม่มีการนำเข้าซ้ำ

## สิ่งที่เพิ่มและแก้ไข

- เข้าสู่ระบบผ่าน Google; บัญชีใหม่ส่งคำขอและรอผู้ดูแลอนุมัติก่อนอ่านข้อมูล
- ผู้ดูแลอนุมัติ ระงับสิทธิ์ และเปลี่ยนบทบาทจาก “จัดการ → สิทธิ์สมาชิก”
- ผู้เข้าชมอ่านได้; ผู้แก้ไขเพิ่ม/แก้ไขเกม หัวข้อ และรูป; ผู้ดูแลจัดการสมาชิกเพิ่มเติม
- ตรวจสิทธิ์ใน API ทุกคำขอ และ SQL ใช้ RLS เพื่อป้องกันการเรียก Supabase โดยตรง
- โหมดสว่าง/มืด เริ่มตามเครื่องและจดจำตัวเลือก; รองรับมือถือ
- เกมไม่จำกัดชื่อ เพิ่มเกมและอัปโหลดรูปเองได้ (PNG/JPEG/WebP สูงสุด 3 MB)
- รูปอยู่ใน private bucket และเปิดผ่าน API ที่ตรวจสิทธิ์
- ค้นทั้งหัวข้อ คำตอบ สรุป รหัส FAQ และชื่อหมวดหมู่; ค้นบางส่วนของข้อความได้
- แสดงจำนวนจริงและแบ่งหน้า 24/48/96 รายการ ไม่ตัดที่ 60; ปุ่มแก้ไขในหน้าคำตอบ
- เลิกใช้รหัสผู้ดูแลร่วมและ Secret Key สำหรับเขียนข้อมูล; ใช้บัญชีผู้ใช้ที่ได้รับสิทธิ์
- ไม่ต้องใช้ OpenAI/AI API การค้นหาเป็นการค้นข้อความจาก Supabase ไม่ใช่ semantic search

## ติดตั้งตามลำดับนี้

SQL ในชุดนี้สำหรับฐานข้อมูล NEXUS เดิมที่มี `games`, `game_entries`, คอลัมน์ `topic` และฟังก์ชัน `nexus_catalog()` อยู่แล้ว อย่าใช้กับฐานข้อมูลว่างโดยไม่เตรียม schema เดิมก่อน

### 1. เตรียม Supabase

เปิดโปรเจกต์ [Nexus Game Data Center](https://supabase.com/dashboard/project/esggoqvrwjdzszahzxlp) → SQL Editor → New query แล้วรัน `supabase/prepare-v1.3.sql` ทั้งไฟล์

ไฟล์นี้เพิ่มตารางสมาชิก รูปเกม และที่เก็บรูปแบบ private ยังไม่ปิดการอ่านข้อมูลเดิมของผู้ไม่เข้าสู่ระบบ และยังไม่เพียงพอที่จะทำให้ฐานข้อมูลทั้งหมดเป็นส่วนตัว ต้องทำขั้นตอน Activate ด้านล่างให้ครบ

เก็บ `nexus_private` ไว้นอก Exposed schemas ของ Data API (ค่าปกติไม่เปิด schema นี้)

### 2. ตั้งค่า Google Login

1. ใน Google Cloud / Google Auth Platform สร้าง OAuth Client แบบ **Web application**
2. ตั้งค่า Audience และข้อมูลแอป; หากยังอยู่ Testing ให้เพิ่มอีเมลที่จะทดสอบเป็น Test users
3. Authorized JavaScript origins: `https://nexus-game-data-center.vercel.app`
4. Authorized redirect URIs: `https://esggoqvrwjdzszahzxlp.supabase.co/auth/v1/callback`
5. ใน Supabase → Authentication → Sign In / Providers → Google เปิดใช้งานแล้วใส่ **Google Client ID และ Google Client Secret**
6. ใน Supabase → Authentication → URL Configuration ตั้ง Site URL เป็น `https://nexus-game-data-center.vercel.app`
7. เพิ่ม Redirect URL: `https://nexus-game-data-center.vercel.app/api/auth/callback**`

ท้าย `**` ในข้อ 7 ใช้รองรับ query `state` ของ callback; ระบุโดเมนจริงให้ตรง หลีกเลี่ยง wildcard ทั้งโดเมน

Google Client Secret ตั้งใน Supabase เท่านั้น ไม่ใช่ Supabase Secret Key และไม่ต้องใส่ในโค้ดเว็บ

หากเปลี่ยนโดเมนให้เปลี่ยน JavaScript origin, Supabase Site URL, Redirect URL และ Vercel SITE_URL ให้ตรงกัน ใช้โดเมนหลักในการเข้าสู่ระบบ ไม่ใช้ URL Preview ที่ยังไม่ได้ตั้งค่า

อ้างอิง: [Supabase Google Login](https://supabase.com/docs/guides/auth/social-login/auth-google), [Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)

### 3. ตั้งค่า Vercel และอัปโหลดโค้ด

เปิดโปรเจกต์ใน Vercel → Settings → Environment Variables เพิ่มใน Production:

| ชื่อ | ค่า |
| --- | --- |
| `SUPABASE_URL` | `https://esggoqvrwjdzszahzxlp.supabase.co` |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable key ของโปรเจกต์เดียวกัน จาก Supabase Settings → API Keys |
| `SITE_URL` | `https://nexus-game-data-center.vercel.app` |
| `SESSION_SECRET` | ค่าสุ่มส่วนตัวอย่างน้อย 32 ตัวอักษร ใช้เข้ารหัสคุกกี้ |

สร้าง SESSION_SECRET บนเครื่องของคุณ:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

ห้ามใช้ข้อความตัวอย่างเป็นคีย์จริง ห้ามเติม `NEXT_PUBLIC_` ให้ SESSION_SECRET และห้ามอัปโหลดไฟล์ `.env` ที่มีค่าจริงไป GitHub

รุ่นนี้ไม่อ่าน `SUPABASE_SECRET_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_ACCESS_KEY` หรือ `OPENAI_API_KEY` สามารถลบตัวแปรเก่าที่ไม่ใช้จากโปรเจกต์นี้ได้

1. แตก ZIP ก่อน แล้วเปิดโฟลเดอร์ที่เห็น `package.json` และ `app` อยู่ระดับเดียวกัน
2. แทนที่ซอร์สเก่าใน GitHub ด้วยไฟล์และโฟลเดอร์ของรุ่นนี้ทั้งหมด
3. ถ้า GitHub ปุ่มเลือกไฟล์เลือกโฟลเดอร์ไม่ได้ ให้ใช้ **GitHub Desktop**: Clone repository → คัดลอกทั้งชุดเข้าโฟลเดอร์ repository → Commit → Push origin (หรือใช้การลากโฟลเดอร์ในหน้า Upload files หากเบราว์เซอร์รองรับ)
4. Vercel Framework: **Next.js**, Node: **22.x**, Build: `npm run build`, Install: `npm ci`
5. Root Directory ต้องเป็นโฟลเดอร์ที่มี `package.json` และ `app`; ถ้าอัปโหลดทั้งชุดที่ root ให้ใช้ค่า root เริ่มต้น
6. Deploy/Redeploy หลังตั้ง Environment Variables

ZIP มีโฟลเดอร์ `app` จริง ไม่ใช่เพียงไฟล์ `package.json` จึงแก้ต้นเหตุ “Couldn't find any pages or app directory” เมื่ออัปโหลดครบ

### 4. ตั้งผู้ดูแลคนแรก

1. เปิดเว็บรุ่น 1.3 แล้วเข้าสู่ระบบด้วยบัญชี Google ของเจ้าของเว็บ
2. เว็บจะแสดง “ส่งคำขอสิทธิ์แล้ว” และสร้างแถว `nexus_members` สถานะ pending
3. เปิด `supabase/bootstrap-admin.sql` เปลี่ยน `REPLACE_WITH_YOUR_GOOGLE_EMAIL` เป็นอีเมลที่ใช้เข้าสู่ระบบจริง แล้วรันใน SQL Editor

ระบบไม่ให้ผู้สมัครคนแรกกลายเป็นผู้ดูแลอัตโนมัติ เพื่อไม่ให้บุคคลอื่นได้สิทธิ์ก่อนเจ้าของ

### 5. เปิดใช้การป้องกันข้อมูลทั้งหมด (จำเป็น)

หลังมีผู้ดูแลคนแรกแล้ว รัน `supabase/activate-v1.3.sql` ใน SQL Editor ทั้งไฟล์

ขั้นตอนนี้ถอนสิทธิ์อ่านแบบ anonymous บนตารางเกม/หัวข้อและ catalog และกำหนด RLS ตามสมาชิก จึงทำให้เว็บรุ่นเก่าที่อ่านแบบสาธารณะใช้ไม่ได้ ควรทำในช่วงเปลี่ยนไปใช้ 1.3 และอย่ารัน SQL รุ่นเก่าที่เปิดการอ่านสาธารณะทับภายหลัง

**ห้ามถือว่าข้อมูลเป็นส่วนตัวหากยังไม่ได้รัน Activate สำเร็จ** หน้าล็อกอินอย่างเดียวไม่ปิดการเข้าฐานข้อมูลโดยตรง

รีเฟรชหน้าเว็บ แล้วทดสอบด้วยเจ้าของเว็บและบัญชีทดสอบอีกบัญชีตามรายการด้านล่าง เก็บหรือจำกัดการเข้าถึง deployment รุ่นเก่าที่เคยใช้สิทธิ์ระดับ service เพื่อไม่ให้เหลือเส้นทางจัดการเก่า

## ใช้งานหลังติดตั้ง

- อนุมัติคนใหม่: จัดการ → สิทธิ์สมาชิก → สถานะ “อนุมัติแล้ว” → เลือกบทบาท → บันทึก → ยืนยัน
- ถอนสิทธิ์: เลือก “ระงับสิทธิ์” แล้วบันทึก คำขอข้อมูลครั้งถัดไปถูกปฏิเสธ หน้าเว็บตรวจซ้ำทุก 60 วินาทีและเมื่อกลับมาโฟกัส (ไม่สามารถเรียกคืนข้อความที่ผู้ใช้เคยคัดลอกหรือดาวน์โหลดแล้ว)
- เปลี่ยนผู้ดูแล: แต่งตั้งผู้ดูแลคนที่สองก่อน ให้คนนั้นปรับสิทธิ์บัญชีเดิม ระบบป้องกันการเปลี่ยนสิทธิ์ตัวเองและการลบผู้ดูแลคนสุดท้าย
- เพิ่มเกม: จัดการ → จัดการเกม กำหนดชื่อและรหัสเกมภาษาอังกฤษ/ตัวเลข/ขีดกลาง/ขีดล่าง รหัสเปลี่ยนภายหลังไม่ได้
- รูปเกม: จัดการ → รูปเกม → เลือกเกม → เลือกรูป → บันทึกรูปเกม; ลบรูปกลับไปใช้ตัวอักษรย่อได้
- แก้ไขหัวข้อ: เปิดคำตอบ → แก้ไขหัวข้อนี้ → บันทึก
- รูปเกมใหม่ไม่จำเป็นต้องสร้างด้วย AI และไม่มีรายชื่อเกมที่จำกัดไว้ในโค้ด

## ตรวจสอบหลังเปิดใช้งาน

1. เปิด Incognito ที่ยังไม่ล็อกอิน: ต้องเห็นหน้าเข้าสู่ระบบ และ `/api/catalog` ต้องตอบ 401
2. ล็อกอินบัญชีใหม่: ต้องเห็นหน้ารออนุมัติและอ่านหัวข้อไม่ได้
3. อนุมัติเป็น viewer: ค้นและอ่านได้ แต่เพิ่มเกม/หัวข้อ/รูปหรือปรับสิทธิ์ไม่ได้
4. เปลี่ยนเป็น editor: เพิ่มเกม รูป และแก้ไขหัวข้อได้ แต่จัดการสิทธิ์ไม่ได้
5. ระงับสิทธิ์ขณะเปิดเว็บ: คำขอถัดไปต้องถูกปฏิเสธ และหน้าเว็บกลับไปหน้ารอ/ระงับภายในรอบตรวจ
6. ทดสอบรูปด้วยบัญชีที่อนุมัติและ Incognito รวมทั้งสลับธีมบนมือถือ
7. ทดสอบจำนวนข้อมูลเกิน 60 และหน้าสุดท้ายว่าครบ ไม่ซ้ำ

การพัฒนาได้ตรวจ production build, TypeScript และชุดทดสอบ API แบบจำลองแล้ว ยังไม่ได้ทดสอบ Google OAuth กับ Client ID จริงหรือเปิดใช้ SQL บนฐานข้อมูล production ให้คุณ ออโตรีวิวปฏิเสธการทดลองแก้สิทธิ์บนฐานข้อมูลจริงแม้ตั้งใจ rollback จึงคง SQL เป็นไฟล์สำหรับขั้นตอนติดตั้ง การตรวจ Security Advisor ของฐานข้อมูลเดิมไม่พบรายการเตือนในเวลาตรวจ แต่ไม่ได้เป็นผลรับรอง SQL ใหม่
